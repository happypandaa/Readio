# Readio 技术方案（v1）

> 配合 `01-产品需求.md`（做什么）和 `03-UI原型.html`（长什么样）阅读。本文档说明怎么实现。
> 原则：**简单优先**。不引入本文档没列出的库；需要新增依赖时先说明理由。

## 1. 总体架构

```
浏览器（React + IndexedDB）
   │  只发 OpenAI 格式的请求到同源 /v1/*
   ▼
server.js（Node + Express，唯一的后端文件）
   ├── POST /v1/chat/completions → 原样转发 DeepSeek
   ├── POST /v1/audio/speech     → 转成豆包语音格式，解码 base64，返回 mp3
   └── 生产模式下提供 dist/ 静态文件
```

- 所有业务数据存在浏览器 IndexedDB，后端**不存任何数据**。
- 密钥只在 `.env` 里，由 server.js 读取，**不出现在前端代码和浏览器里**。
- 前端只认 OpenAI 格式，以后换 LLM 或 TTS 服务，只改 server.js。

## 2. 技术栈与依赖

| 用途 | 选择 |
|---|---|
| 运行环境 | Node 20.6 或以上（需要内置 `fetch` 和 `--env-file`） |
| 前端 | React 18 + Vite，**纯 JavaScript（JSX），不用 TypeScript** |
| 本地数据库 | `dexie` + `dexie-react-hooks`（`useLiveQuery`） |
| 后端 | `express` |
| 开发时同时启动前后端 | `concurrently`（devDependency） |
| 英文字体 | `@fontsource-variable/newsreader`（本地打包字体，不依赖 Google Fonts，国内网络更稳） |
| 路由 | 不用路由库，自己写一个约 20 行的 hash 路由 hook |
| 状态管理 | 不用 Redux/Zustand。数据用 `useLiveQuery` 读 IndexedDB，界面状态用组件 state |
| UI 组件库 | 不用。样式从原型的 CSS 迁移 |

## 6. 后端 server.js

全部逻辑在一个文件里，目标 80 行以内。

### 6.1 通用

- `express.json({ limit: '1mb' })`
- 生产模式：如果 `dist/` 存在，`express.static('dist')`，其他 GET 请求返回 `dist/index.html`
- 统一错误格式：`{ "error": { "message": "简短原因" } }`
  - 上游返回非 2xx 或业务错误码：返回 502，message 带上游的简短原因
  - 网络错误：返回 502，message 为 `无法连接 DeepSeek` 或 `无法连接豆包语音`
- 启动时检查必填环境变量，缺少时打印清楚是哪个，并退出

### 6.2 POST /v1/chat/completions

- 请求体原样转发到 `https://api.deepseek.com/chat/completions`
- 如果请求体没有 `model`，用 `DEEPSEEK_MODEL` 补上
- Header：`Authorization: Bearer ${DEEPSEEK_API_KEY}`、`Content-Type: application/json`
- v1 不需要流式，`stream` 一律设为 `false`
- 原样返回 DeepSeek 的 JSON

### 6.3 POST /v1/audio/speech

**接收（OpenAI 格式）**：`{ "input": "要朗读的文本", "voice": "可选，默认 DOUBAO_VOICE" }`

**调用豆包语音 HTTP 接口（一次性合成，非流式）**：
- 地址：`https://openspeech.bytedance.com/api/v1/tts`
- Header：`Authorization: Bearer;${DOUBAO_TOKEN}`（注意是**分号**，不是空格）
- 请求体：

| 字段 | 值 |
|---|---|
| `app.appid` | `DOUBAO_APPID` |
| `app.token` | `DOUBAO_TOKEN` |
| `app.cluster` | `DOUBAO_CLUSTER` |
| `user.uid` | `readio` |
| `audio.voice_type` | voice |
| `audio.encoding` | `mp3` |
| `audio.speed_ratio` | `1.0`（固定，语速由前端播放速度控制） |
| `request.reqid` | 每次新生成：`crypto.randomUUID()` |
| `request.text` | input |
| `request.operation` | `query` |

**返回处理**：
- 豆包返回 JSON，成功时音频在 `data` 字段，为 base64 编码
- 判断成功码（文档中为 `code === 3000`），失败时按 6.1 返回错误
- 把 `data` 用 `Buffer.from(data, 'base64')` 解码，以 `Content-Type: audio/mpeg` 返回二进制

**校验**：`input` 为空返回 400。文本长度上限以豆包文档为准，超出返回 400 并说明原因。

> ⚠️ 豆包语音有多个版本的接口，字段以[官方文档](https://www.volcengine.com/docs/6561/79820)为准。如果所选音色要求使用新版接口（例如需要 `X-Api-App-Id`、`X-Api-Access-Key`、`X-Api-Resource-Id` 等请求头），只改这个路由的实现，**对前端的输入输出格式保持不变**。

## 7. 前端数据（db.js）

数据库名 `readio`，版本 1。

```js
db.version(1).stores({
  articles:       '++id, sortAt',
  sentences:      '[articleId+idx], articleId',
  audios:         'key, articleId, status',
  lookups:        'key',
  savedSentences: '++id, createdAt, [articleId+idx]',
  savedWords:     '++id, createdAt, [articleId+idx]',
  settings:       'key',
});
```

### 7.1 字段

**articles**
| 字段 | 说明 |
|---|---|
| id | 自增 |
| title | 标题 |
| sentenceCount | 句子数 |
| createdAt | 添加时间（毫秒时间戳） |
| lastStudiedAt | 最近进入学习页的时间，未学习为 null |
| sortAt | 排序用：`lastStudiedAt ?? createdAt`，两个时间变化时同步更新 |
| lastIndex | 上次位置，从 0 开始 |
| finished | 是否已学完 |

**sentences**
| 字段 | 说明 |
|---|---|
| articleId, idx | 联合主键，idx 从 0 开始 |
| text | 英文 |
| paraStart | 是否是段落第一句（第一篇第一句为 false） |
| zh | 中文翻译缓存，没有为 null |

**audios**
| 字段 | 说明 |
|---|---|
| key | 主键，见下表 |
| articleId | 句子音频为文章 id，其他为 null |
| status | `pending` / `ok` / `fail` |
| blob | mp3 Blob，`ok` 时才有 |
| updatedAt | 时间戳 |

key 规则：
| 类型 | key |
|---|---|
| 文章句子 | `s:{articleId}:{idx}` |
| 单词发音 | `w:{单词小写}` |
| 原文已删除的收藏句子 | `f:{savedSentenceId}` |

**lookups**：`key = 单词小写 + '|' + 原句`，`result = { lemma, phonetic, pos, meaning }`

**savedSentences**：`text, zh, zhStatus('pending'|'ok'|'fail'), articleId, articleTitle, idx, createdAt`

**savedWords**：`word, lemma, phonetic, pos, meaning, sentence, articleId, articleTitle, idx, createdAt`
判断是否已收藏：同 `articleId + idx`，且 `word` 小写相等。

**settings**：`{ key, value }`，目前有：
| key | 默认值 | 说明 |
|---|---|---|
| `speed` | `1.0` | 播放语速 |
| `lastTab` | `articles` | 列表页上次选中的标签 |
| `favView` | `{ sentences: 'full', words: 'full' }` | 两个收藏标签各自的显示方式，`full` 或 `compact` |

### 7.2 关键操作（都写在 db.js 里，页面只调用函数）

- `addArticle(title, text)`：一个事务内写入 article、所有 sentences、每句一条 `pending` 的 audio；返回 id 后通知音频队列
- `renameArticle(id, title)`：只改文章标题，**不改**收藏里的 `articleTitle`
- `deleteArticle(id)`：一个事务内删除 article、它的 sentences、`articleId` 等于它的 audios。收藏不动
- `touchArticle(id)`：进入学习页时调用；更新 `lastStudiedAt` 和 `sortAt`；如果 `finished` 为 true，则改为 false 并把 `lastIndex` 设为 0
- `setLastIndex(id, idx)`、`setFinished(id)`
- 收藏相关：`toggleSavedSentence`、`toggleSavedWord`、`removeSaved`、`restoreSaved`（撤销用）

启动时调用一次 `navigator.storage.persist()`，降低浏览器清理数据的概率。

## 8. 文本处理（text.js）

**分句 `splitSentences(text)`**，原型里有可直接参考的实现：
1. 去掉 `\r`，按空行（`\n\s*\n`）切成段落；段内连续空白合并为一个空格
2. 每段用 `new Intl.Segmenter('en', { granularity: 'sentence' })` 切句，`trim()` 后去掉空串
3. 每段第一句标记 `paraStart`（全文第一句除外）

**分词 `tokenize(sentence)`**：用正则 `/[A-Za-z]+(?:['’-][A-Za-z]+)*/g` 找出单词，返回 `[{ type: 'word'|'text', value }]`，学习页按此渲染，只有 word 可点击。

**自动标题 `autoTitle(firstSentence)`**：去掉末尾标点，超过 8 个单词时取前 8 个并加 `…`。

## 9. AI 接口（api.js）

### 9.1 底层

- `chat(messages, { json })`：POST `/v1/chat/completions`，`temperature: 0.3`；`json` 为 true 时加 `response_format: { type: 'json_object' }`；返回 `choices[0].message.content`
- `speech(text)`：POST `/v1/audio/speech`，返回 `Blob`
- 两者遇到非 2xx：读取 `error.message` 抛出 `Error`，界面按需求文档第 7 节显示

### 9.2 句子翻译 `translateSentence(sentence)`

- system：`你是英语翻译。把用户给的英文句子翻译成自然、准确的简体中文。只输出译文，不要解释，不要加引号。`
- user：句子原文
- 结果写入 `sentences.zh`；如果这句已被收藏，同时更新收藏里的 `zh`、`zhStatus`

### 9.3 查词 `lookupWord(word, sentence)`

先查 `lookups` 缓存，命中直接返回。未命中时：
- system：
  ```
  你是英语词典助手。根据单词在给定句子中的用法，返回 JSON：
  {"lemma": 原形（与原词相同则为 null）, "phonetic": 美式音标，带斜杠, "pos": 词性缩写（n. v. adj. adv. prep. conj. pron. phr. 之一）, "meaning": 中文释义}
  meaning 要求：先给最常见的义项，再用"（这里指）……"说明在这句话里的意思；不超过 40 个汉字。只输出 JSON。
  ```
- user：`单词：{word}\n句子：{sentence}`
- 解析失败视为查询失败
- 成功后写入 `lookups`

## 10. 音频生成队列（audioQueue.js）

单例模块，不依赖 React。

- `start()`：应用启动时调用。把 `audios` 中所有 `status = 'pending'` 的句子音频，按文章 `createdAt`、句子 `idx` 排序后入队
- `enqueueArticle(articleId)`：添加文章后调用
- `retryFailed(articleId)`：把该文章所有 `fail` 改为 `pending` 并入队
- **并发 3**（常量，方便调整）；按入队顺序处理
- 单个任务：读取句子文本 → `speech(text)` → `db.audios.update(key, { status: 'ok', blob })`
  - 失败自动重试 2 次，间隔 1 秒、3 秒；仍失败则 `status: 'fail'`
  - 写入前检查这条 audio 记录是否还存在（文章可能已被删除），不存在就丢弃结果
- 界面不需要队列主动通知：列表页、学习页都用 `useLiveQuery` 统计 audios 状态，数据一变界面自动更新

**按需生成**（不进队列，直接调用并缓存）：
- `ensureAudio(key, text)`：有 `ok` 记录直接返回 blob；否则调用 `speech`，写入后返回。用于单词发音、原文已删除的收藏句子

## 11. 播放（usePlayer.js）

学习页使用，一个页面只有一个 `HTMLAudioElement`。

**状态**：`cur`（当前句）、`playing`、`waiting`（等待音频）。

**`playFrom(i)`**：
1. 设 `cur = i`，写入 `lastIndex`
2. 读 `audios` 中 `s:{articleId}:{i}`：
   - `ok`：用 `URL.createObjectURL(blob)` 设为 `audio.src`（**先 revoke 上一个 URL**），`playbackRate = speed`，`play()`
   - `pending`：`waiting = true`，等到该记录变为 `ok` 后自动播放（用 `liveQuery` 订阅或轮询 500ms 均可）
   - `fail`：提示失败（带「重试」），直接 `playFrom(i + 1)`
3. `ended` 事件：间隔 300ms 后 `playFrom(i + 1)`；如果已是最后一句，`playing = false`，调用 `setFinished`，提示 `已读完这篇文章`

**其他**：
- `pause()`：暂停，不改变 `cur`
- `toggle()`：暂停中则 `playFrom(cur)`
- `step(±1)`：播放中则 `playFrom(cur ± 1)`；暂停中只改 `cur`
- 语速改变时立即设置 `audio.playbackRate`，并写入 settings
- 离开学习页：暂停、清空 src、revoke URL

**自动滚动**：
- `cur` 变化时，如果该句不在可视区域（顶部 70px 以下、底部播放栏以上），`scrollTo` 平滑滚动到屏幕约 30% 的高度
- 程序滚动期间（约 900ms）忽略 scroll 事件；播放中用户手动滚动，则关闭自动跟随，显示「回到当前句」

原型里 `playFrom`、`scrollToCur` 和滚动监听的逻辑可直接参考，只是把模拟计时换成真实音频事件。

## 12. 学习页正文：段落模式（ArticleText.jsx、SentenceToolbar.jsx）

**结构**（与原型一致）：
```
<p class="para">                       每个段落一个 <p>
  <span class="sx" data-i="0">         每句一个 span，句子之间用一个空格分隔
    <span class="w" data-w="Rail">Rail</span> companies …
    <span class="mini-star">★</span>   已收藏的句子在句末显示
  </span>
  <span class="sx-zh">译文</span>       展开翻译时紧跟在该句后面，CSS 为 display: block，段落在此断开
  <span class="sx" data-i="1">…</span>
</p>
```
- 当前句加 `cur` 类；悬停加 `hov` 类；从收藏定位过来时加 `flash` 类约 2 秒
- 已收藏的生词：对应 `.w` 加 `saved` 类（同一句、同一单词小写相等）
- 句子 span 需要 `box-decoration-break: clone`，跨行时每行都有完整的背景和圆角

**工具条定位**：
- 工具条是正文区里一个 `position: absolute` 的元素，**整页只有一个**，根据目标句子移动
- 用目标句子 span 的 `getClientRects()` 取第一行矩形：放在它左上方（`top = 第一行.top - 工具条高 - 4`，`left = 第一行.left - 6`，并限制在正文列内）
- 上方空间不足（距离视口顶部小于 64px）时，放到最后一行矩形的下方
- 以下时机重新计算位置：目标句变化、翻译展开/收起、收藏状态变化、窗口 resize

**悬停逻辑**：
- `mouseover` 到某句：如果当前没有悬停句，立即显示；如果从另一句移过来，延迟 160ms 再切换（期间进入工具条则取消切换）
- 离开句子且不是进入工具条、离开工具条且不是回到该句：延迟 220ms 隐藏
- 查词卡片打开时忽略悬停，并隐藏工具条
- 用 `matchMedia('(hover: none)')` 判断触屏设备；触屏时工具条始终跟随当前句

原型里 `renderSents`、`drawBar` 及其事件监听的逻辑可以直接参考。

## 13. 路由（router.js）

| hash | 页面 |
|---|---|
| `#/` | 列表页 |
| `#/study/:id` | 学习页，定位到 `lastIndex` |
| `#/study/:id?focus=N` | 学习页，定位到第 N 句（从 0 开始）并闪烁高亮，用于「回到原文」 |

文章不存在时回到 `#/`。用 hash 路由的好处：刷新页面停留在原处，`npm start` 时服务端也不需要额外的路由配置。

## 14. 样式

- 原型 `03-UI原型.html` 中 `<style>` 的内容按区域拆到 `src/styles/` 下，**类名尽量保持一致**，方便对照
- `:root` 设计令牌原样放进 `tokens.css`，包括深色模式（跟随系统）
- 「原型面板」相关的样式和代码**不要迁移**
- 窄屏（≤640px）适配以原型为准：弹窗（含文章详情弹窗）从底部弹出、查词卡片变为底部弹出、句子工具条固定跟随当前句
- 英文字体：`import '@fontsource-variable/newsreader'`，CSS 中 `--font-en` 首选 `"Newsreader Variable"`

## 16. 注意事项

- **自动播放限制**：浏览器要求用户先有交互才能播放音频。本产品的播放都由点击触发，正常情况下不会遇到；如果 `play()` 抛出 `NotAllowedError`，把状态重置为暂停即可。
- **Blob URL**：每次切换音频前 revoke 上一个，避免内存增长。
- **豆包限流**：如果频繁出现限流错误，把队列并发从 3 降到 2。
- **不要**把 API Key 写进前端代码或提交到仓库。
- **不要**在后端存储任何用户数据。
- 遇到本文档没覆盖的产品问题（交互、文案、视觉），先停下来问，不要自行决定。
