# Readio 交接说明

Readio 是一个个人自用的英语听读 Web 应用：粘贴英文文章，逐句听、逐句读，收藏句子和生词，收藏可以随时回到原文。

这个文件夹是产品设计的全部交付物，实现时以这里为准。

## 文件说明

| 文件 | 内容 | 用途 |
|---|---|---|
| `01-产品需求.md` | 页面、交互、状态、文案、验收清单 | 决定"做什么" |
| `02-技术方案.md` | 架构、目录、数据表、接口、开发步骤 | 决定"怎么做" |
| `03-UI原型.html` | 可点击的原型，示例数据 | 决定"长什么样"，样式可直接迁移 |

**阅读顺序**：本文件 → 需求文档 → 在浏览器里打开原型实际点一遍 → 技术方案。

**冲突时以谁为准**：交互和文案以需求文档为准；视觉以原型为准；技术实现以技术方案为准。

## 原型怎么看

直接用浏览器打开 `03-UI原型.html`，不需要启动服务。

- 原型里的播放、音频生成、翻译、查词都是**模拟**的，用来展示交互和状态
- 列表页点文章会打开文章详情弹窗；学习页是段落模式，鼠标移到句子上会出现句子工具条；句子、生词标签右侧可以切换展开 / 紧凑
- 左上角（窄屏在右上角）的「原型面板」可以切换：查词失败、翻译失败、深色模式、空状态。**这个面板不需要实现**
- 键盘快捷键在原型里已经可用：空格、←、→、T、S、Esc
- 样式和设计令牌在原型的 `<style>` 中，实现时按技术方案第 14 节迁移

## 实现的工作方式

1. 按技术方案第 15 节的步骤顺序开发，**一次只做一步**
2. 每步完成后停下来，说明做了什么、怎么验证，等确认后再继续
3. 遇到文档没写清楚的产品问题（交互、文案、视觉），先问，不要自行决定
4. 不引入技术方案没列出的依赖；确实需要时先说明理由

## 开始前需要准备

- Node 20.6 或以上
- DeepSeek API Key
- 豆包语音的 AppID、Access Token、英文音色 ID（火山引擎控制台开通语音合成后获取）

这些填进项目根目录的 `.env`，格式见技术方案第 4 节。
